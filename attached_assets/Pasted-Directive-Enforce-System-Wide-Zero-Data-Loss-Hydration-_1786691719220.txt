1. UNIVERSAL HYDRATION LOCK (Read-Before-Write):
- On app launch, ALL stores must start in a read-only unhydrated state (isHydrated = false).
- STRICTLY BLOCK any outbound write or sync to Firebase while isHydrated is false.
- A store becomes hydrated (isHydrated = true) ONLY AFTER the initial snapshot has successfully arrived from Firebase.

- No sync hook, store subscriber, or effect is allowed to write an empty array [] or empty object {} to any Firebase root path (/menuItems, /inventory, /customers, /tables, /orders, /expenses, /settings).

  * /tables: Auto-populate with default restaurant tables (Ground Floor, Cabins, First Floor) and sync to Firebase.
- This must execute seamlessly in the background on startup without requiring any manual shell commands.

4. TRANSACTIONAL MERGE SAFETY:
- Customer ledgers, repayments, and order history must always append/merge without overwriting or resetting historical records.
