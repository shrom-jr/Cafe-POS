# POS Inventory Auto-Deduction & Void Restoration

## Deduction on Dispatch
`sendToKitchen` (usePOSStore.ts) calls `useInventoryStore.getState().deductInventoryForSale(unsentItems)` BEFORE the `set()` call. It passes all draft (unsent) items. `deductInventoryForSale` looks up `invMappings` by `menuItemId` and deducts `mapping.deductQty × quantity` from the matching product, then logs a `type: 'Sale'` InventoryMovement.

## Void Restoration
`voidOrderItem` calls `useInventoryStore.getState().restoreInventoryForVoid([...])` BEFORE the `set()` call, but only when `targetItem.kitchenStatus === 'sent' || targetItem.sentToKitchen`. It adds stock back (no `Math.max` cap) and logs a `type: 'Correction'` movement.

## invMappings — Source and Format
```ts
{ id, menuItemId, productType: 'alcohol'|'beverage'|'cigarette', productId, deductQty }
```
- `deductQty` = ml for alcohol/wine, 1 for beer/soft drinks, 1 for cigarettes (sticks)
- Auto-generated by `scripts/seedInventory.mjs` which fetches `menu/items` and name-matches

**Spirit items** follow pattern `"{Brand} ({size})"` where size → ml:
- 30 ml=30, 60 ml=60, 90 ml=90, Quarter=180, Half=375, Full=750
- Wine items match exact name → deductQty 750 ml per bottle

**Why:** Firebase sync push effects in useFirebaseSync.ts automatically fan state changes (products + invMovements) to Firebase; no manual push needed after store mutations.

**How to apply:** When adding new inventory-tracked menu items, run `node scripts/seedInventory.mjs` to regenerate mappings. Never hand-edit invMappings in Firebase directly — the seed script overwrites the entire node.
